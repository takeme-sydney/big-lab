01 · Research definition

誤差、説明変数、将来の性能評価を混同しない。

geometry QCはdesign geometryに対する偏差を測る研究です。print-processは誤差を説明しうる記録層であり、力学・光学・透過性はGate 7まで別の測定対象です。

01

Geometry error Primary measurement domain

design / nominal geometryに対する実測構造体の偏差。radius、wall thickness、surface fidelity、chordal、volume、shrinkage、interlayerを別変数として扱います。

Output: predeclared geometry metric(s), with units and source mesh
02

Print-process traceability Explanatory record layer

fabrication strategy、layer thickness、slice angle、overhang angle、support removal、material / bioink batch、printer・optics settingsを記録し、geometry errorの説明要因として比較します。

Not an outcome, biological proxy, or performance claim
03

Extended characterization Future scope · Gate 7

Young's modulus、transparency、refractive index / power、corneal permeabilityは専用測定を要する別scopeです。geometry QCだけからこれらを主張しません。

Output: future characterization charter, not a Gate 0–6 endpoint
Q

推奨するprimary research question proposal · PI confirmation required

「PIが定義するcurved corneal constructとdesign referenceについて、文書化したacquisition tierの下で、PIが選ぶgeometry-error endpointはdesign targetからどの程度偏差するか？」最初のpilotでは、primary endpointを一つに固定し、他のmetricはsecondary / exploratoryとして記録します。

radius_deviation_mmbest-fit radius − design radius · mm
thickness_variation_mmlocal distribution vs design thickness · mm
surface_rmse_mmregistered surface fidelity · mm
chordal_error_mmlayer-wise faceting deviation · mm
volume_change_fractionmeasured vs design volume · fraction
shrinkage_rate_fractionas-printed vs post-process · fraction
interlayer_misalignment_mmadjacent-layer offset · mm
registration_rmse_mmfit-quality diagnostic, not geometry error · mm
!

Registration RMSEの位置づけ

registration_rmse_mmはdesign meshへの位置合わせ品質を示す診断指標です。高い値のsampleはgeometry errorを自動的に確定せず、human reviewへ回します。誤差成分を一つの総合scoreへ統合しません。

02 · Evidence & provenance

文献のgapと、まだ実験で示していないことを分ける。

このroadmapはYuan et al. (2026)のreviewが示したgeometry reporting gapを出発点にします。portfolio demoはpipelineの構造確認に限り、experimental evidenceではありません。

Primary source · review evidence

Systematic geometry-error reporting is the stated gap

“To our knowledge, no study has systematically reported measured geometric errors … as a function of curvature in such constructs.”

Yuan et al. (2026) Section 5は、test domeを条件を変えて印刷し、高解像度scanまたはOCTで実測してcurvature angleとdimensional errorを対応づける案を示します。本roadmapはこの提案を実験計画へ翻訳するもので、同reviewが特定の手法の優劣を実証したとは扱いません。

Calibration record

pixel / voxel → mmの前に残す順序

  1. Referenceを確定: known reference（calibration target、CT/OCTのvoxel size等）をcalibration_referenceへ記録する。
  2. Verificationを記録: calibration_confirmedをtrue / falseとして残し、trueならvoxel_or_pixel_sizeを記録する。
  3. Rawを固定: raw_fileは存在しread-onlyのまま保持する。unit conversionはscript化しtestする。
  4. 欠落を測定値に見せない: calibrationがないdataはpixel単位またはnot measurableとして扱い、mm・µm・mm³値へ換算しない。

Design mesh registration

errorを算出する前に、fit品質を分離する。

  1. design / nominal meshまたはCADをversioned referenceとして解決する（design_version）。
  2. 実測meshをdesign meshへ位置合わせする（例: registration_method = ICP + scale）。rigid + scale補正の要否を明記する。
  3. registration_rmse_mmをfit品質として記録する。これはgeometry errorそのものではない。
  4. 事前登録上限を超えるnon-convergenceは自動除外せず、qc_statusとexclusion_reasonでflagする。
  5. design−measured overlay、parameter、failure reasonをconstruct logへ残してhuman reviewへ渡す。
05 · Analysis & data architecture

階層、単位、fit品質を壊さずに解析する。

experimental unitをconstructだけに単純化せず、study → print run → material / bioink batch → construct → Tier B measurement / layerの入れ子を保存します。print runとbatchをgroup化因子として扱います。

Metric equations · from templates/analysis-plan.md

radius_deviation = best_fit_radius − design_radius
wall_thickness_variation = local_thickness(x) − design_thickness(x)
surface_rmse = RMS( measured_surface − design_surface ), over registered region
chordal_error = max deviation of discretised print path from intended smooth curve
volume_change = ( measured_volume − design_volume ) / design_volume
shrinkage_rate = ( as_printed_dimension − post_process_dimension ) / as_printed_dimension

派生指標は、単位・基準面・正負の符号規約を記録します。registration_rmse_mmは上のequation群に含めず、fit品質のdiagnosticとして別に保存します。

extended characterization（力学・光学・透過性）を混同しないこと。
synthetic demo（portfolio）とreal pilot dataを常に区別すること。

必須原則:
- 文献に書かれた事実、ローカルデータから算出した結果、提案、仮定、
  そしてsynthetic demoに由来する数値を、明示的に5つすべて分けて扱う。
- Yuan et al. (2026)がgeometry error（radius、wall-thickness、surface roughness、
  chordal error）の系統的報告不足を指摘した事実と、そこから導いた本ラボの研究提案を混同しない。
- calibration（pixel/voxel → mm）が確認できないデータを、実測値として単位変換しない。
- registration RMSEはfit品質の診断指標であり、geometry errorそのものではない。
- QC threshold（PASS / REVIEW / FAIL）は、portfolio demoの`±0.18mm`を転用せず、
  Gate 0でPI承認のもと新たに設定する。
- constructをhierarchyとして study > print run > material/bioink batch >
  construct（sample） > (Tier Bの場合)測定断面/layer として保持する。
- raw scan / image / OCT出力を変更しない。前処理、除外理由、registration parameterをlogに残す。
- geometry error（radius/thickness/surface/chordal/volume/shrinkage/interlayer）を
  単一スコアへ統合しない。
- 力学（Young's modulus）、光学（transparency、refractive index/power）、
  permeabilityについて、Gate 7の専用測定なしに性能を主張しない。
- wet-lab条件、機器（3D printer、OCT、scanner）利用は、ラボSOP、PI、training、
  該当する承認を優先する。
- 臨床効果、光学性能、生物学的安全性を、geometry QCの結果だけから主張しない。
- synthetic demoの結果を、実験的knowledgeとして引用・報告しない。

実行順:
1. 研究質問とprimary metric（geometry errorのどの成分か）を一文で再掲する。
2. 利用可能なfile、欠けているmetadata（calibration、design reference、
   permission）を監査する。

   のどれかを分類する。
4. experimental hierarchy（study → print run → material/bioink batch → construct（sample） →（Tier B）測定断面/layer、および各水準に紐づく design/method version）を図示する。
5. calibration、design mesh registration手法、metric定義range、
   既知の失敗モード（segmentation失敗、透明試料の取得困難、calibration欠落）を確認する。
6. predeclared QCに基づきsampleを評価する。除外は削除でなくflagとして残す。
7. geometry errorの各成分（radius/thickness/surface/chordal/volume/shrinkage/
   interlayer）を、print-process要因（fabrication strategy、layer厚、
   slice angle、overhang角度）に対して比較・可視化する。
8. 小sample統計またはgrouped validationを使う場合、batchをgroup単位とし、
   leave-one-batch-outまたは同等の検証を実装する。
9. 結果、限界、次の最小実験を、synthetic demoとreal pilotを区別して報告する。
10. HTMLを更新する場合は概念図と実測図、そしてsynthetic demoに由来する図表を
    明確に区別し、sourceと更新日を付ける。

最低限の出力:
- one-sentence research question（geometry errorのどの成分が対象か）
- assumptions / unresolved questions（requirements.md §10の7項目を含む）
- file and data audit
- experimental design table（Tier A / Tier Bのどちらを使うか含む）
- QC and acceptance table（新規設定したPASS/REVIEW/FAIL閾値と根拠）
- analysis plan with equations and units
- risk / mitigation table
- reproducible file outputs and paths
- claims supported / not yet supported（extended characterizationは明示的にnot yet supported）
- next decision and owner

停止条件:
- calibration（pixel/voxel → mm）を復元できない
- design geometry / nominal referenceが不明
- 画像・scan・OCTデータのdata-use permissionが不明
- construct、print run、batchのhierarchyを復元できない
- primary metricまたはQC閾値を結果確認後に変更しようとしている
- geometry QCの結果から力学・光学・透過性・臨床性能を主張しようとしている

停止条件に当たる場合は推測で埋めず、欠けている項目、影響、確認先
（多くの場合PIまたはdecision-log.mdの既存記録）を短く提示する。

PI questions · requirements.md §10

7つの確認事項

  1. radius error、wall-thickness variation、surface roughness、topographic chordal errorのうち、ラボで再現可能に測るのが現在最も難しいのはどれか。
  2. 最初のpilotは、OCT / scan geometry-QC workflowと、bioink・photocrosslinking条件をoutcomeへ結びつけるrun-level registryの、どちらとして始めるのが有用か。
  3. 利用可能な既存データはCAD、複数角度写真、structured light scan、OCT、confocal z-stack、instrument CSVのいずれか。
  4. 3D scanner / OCT / CAD softwareへのアクセスと、必要なtrainingの有無。
  5. dual-layer corneal bioprinting論文（Huang, Yuan et al. 2026）の全文入手可否（現状はURLのみ把握）。
  6. surface roughnessをdesign meshからのsurface RMSEで代替してよいか、それともTier Bでclassical texture roughness（Ra / Rq等）を別途測る必要があるか（§3.1のoperationalizationの妥当性確認）。
  7. material / bioink batchとprint runの実際の入れ子関係（1つのbatchが複数のprint runに供給されるか、print runごとにbatchを調製するか）。§3.3のhierarchyとgroup化因子の定義に影響する。

Interpretation boundary

  • Supported by the source: the review identifies a geometry-error reporting gap and organizes standard measurement methods in Table 3.
  • Proposed here: a staged local-first geometry QC workflow, data hierarchy, and Gate 0–7 decision structure.
  • Not yet supported: real-pilot geometry performance, numeric QC acceptance thresholds, biological function, optical performance, mechanical performance, permeability, or clinical suitability.
  • Synthetic demo only portfolio counts, QC labels, and any derived figure remain non-experimental and are never merged into real-pilot reporting.
