Operating model

AIは実行者。研究者は責任者。

自由度を探索段階で広げ、結論段階で狭めます。研究者が決めるべき内容をClaudeへ委ねると、速くても説明できない解析になります。

研究者が決めるClaudeへ任せられる一緒に確認する
研究問いと意思決定file構造の調査experimental unit
primary outcomeloaderとQC code欠損・除外・変換
倫理・データ利用範囲反復処理と可視化統計手法と仮定

experimental unitを最初に書く。

sample、run、image、field、cellのどれが独立単位かを決めます。ここを曖昧にすると、Claudeが正しく計算しても擬似反復や過大なnが生まれます。

Seven-stage workflow

再現性を作る7段階。

問いと意思決定を固定

何を比較し、その結果で次に何を決めるかを書く。探索、確認、仮説検定を混ぜない。

SAVE → research_question.md

データ境界を定義

experimental unit、sample ID、単位、calibration、欠損表現、利用可能範囲をdata dictionaryへ記録。

SAVE → data_dictionary.csv

実行せずPlanだけ作る

手法、仮定、欠損処理、QC、統計、想定failure mode、必要権限を先に出させる。

CHECK → no execution yet

数sampleでdry run

loader、単位、向き、calibration、label、plotを目視確認してから全件へ広げる。

SAVE → qc_preview.html

中間結果をArtifact化

重要な表、図、処理済みdata、scriptを明示的に保存する。scratch fileのまま残さない。

SAVE → versioned artifacts

Reviewerと人間の検証を分ける

Reviewerは記録との整合を確認。手法の妥当性、臨床的意味、再現実験は担当研究者が確認。

VERIFY → record + domain review

再実行packageとして渡す

rawからfigureまでのscript、environment、README、除外一覧、known limitationsを揃える。

DONE → reproducibility bundle

Artifact anatomy

成果物は、fileだけではない。

Artifactはfigure、processed dataset、report、notebookなどの保存成果です。同じfile名を再保存するとversionが増え、作成過程へ戻れます。

geometry_qc.pngVersion 03
Saved artifact
Local project storage
MESSAGES保存前後の会話と判断
CODE再現用scriptまたはnotebook
EXECUTION LOG実際に走ったcommandの正式記録
ENVIRONMENTlanguageとpackage version
REVIEWReviewerの指摘と対応
CodeとLogが違う場合

Execution Logが実際に走った内容のauthoritative recordです。再現用Codeを修正し、新versionとして保存します。

Verification boundary

Reviewerが確認すること、しないこと。

確認する保証しない
計算していない値を計算済みと報告していないか選んだ解析手法が研究問いに最適か
回答の数値とfileが一致するかdata collectionや実験設計が妥当か
引用が主張を支えるか、DOIが正しいか研究結果が真実か、再現実験で成立するか
承認Planのstepを完了したか臨床判断、診断、患者への適用

Reuse validated work

検証済み手順をSkillにする。

毎回同じ説明を貼るのではなく、承認済みworkflowを手順、tool、QC、停止条件、成果物を含むSkillとして保存できます。

このSessionで承認・検証したworkflowを再利用可能なSkillにしてください。 含める: - triggerとなる課題 - 必要inputとschema - step-by-step procedure - 使用tool / package - QC checksと停止条件 - expected artifacts - failure mode - human review checkpoints 研究室固有のpathや機密情報は含めないでください。
