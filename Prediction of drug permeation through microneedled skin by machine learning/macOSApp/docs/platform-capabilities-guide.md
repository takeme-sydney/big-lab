# Permeation Lab macOS プラットフォーム機能ガイド

更新日: 2026-09-02  
対象: `Prediction of drug permeation through microneedled skin by machine learning/macOSApp`

## 1. このプラットフォームは何をするものか

Permeation Lab は、マイクロニードル処理皮膚における薬物透過研究を支援する macOS アプリです。Yuan et al. (2023) の論文・補足資料・Data S1を読み解く機能と、自分のCSVを使ってデータ監査、可視化、モデル比較、再現実験、未知データ予測を行う機能を一つにまとめています。

主に次のことができます。

- 原著論文、関連文献、数式、図、報告性能を確認する
- 同梱された Data S1 の191観測・11列を検索、可視化、監査する
- 自分の実験CSVを読み込み、Data S1とは分離した状態で解析する
- 原著に記載された統計モデルのプロトコルをローカル実装で再構成する
- 任意の表形式CSVで回帰モデルを比較し、学習済みモデルを保存する
- 学習済みモデルを使って未知CSVを一括予測する
- Fickの2次元有限差分プレビューと、Fick型proxyモデルのエビデンス監査を行う
- 類似研究や in vitro データを読み込み、Data S1や探索的モデル曲線と比較する
- データhash、分割、指標、予測、警告、来歴をJSONまたはCSVとして保存する

機械学習と数値計算はMac内で実行されます。Python、R、クラウドAPI、常時のネットワーク接続は不要です。ただし、アプリ内の一次ソースへのリンクを開く場合はインターネット接続を使用します。

## 2. 2つの研究モード

アプリは、論文の事実と利用者の解析結果が混ざらないよう、画面上部で研究モードを分離しています。

| モード | 使用するデータ | 主な用途 | 結果の扱い |
| --- | --- | --- | --- |
| 論文エビデンス | 同梱された `Yuan 2023 · Data S1` | 原著・補足資料・既報値の閲覧と監査 | 公開一次資料と照合済みの領域 |
| 自分の研究 | 利用者が読み込んだCSV | 可視化、比較、モデル構築、予測、追加検証 | スキーマに合格しても「科学的妥当性未検証」 |

「自分の研究」でData S1と同じ内容のCSVを読み込んでも、論文エビデンスへ自動昇格することはありません。モード、科学的状態、データセットhashはrun記録へ残ります。

画面表示は日本語と英語を切り替えられます。

## 3. 論文エビデンスモードでできること

### 3.1 論文の概要

- 研究の問い、7つの入力、2つの出力、70:30分割という原著の評価設計を確認できます。
- 観測数、薬物数、比較された4手法、原著図数を一覧できます。
- PubMedおよびPMCの全文へ移動できます。
- 公開されていない学習済みモデルや分割行があることを含め、再現可能性の境界を確認できます。

### 3.2 関連論文30報

- マイクロニードル皮膚透過、Fickモデル、機械学習に関する検証済み文献30報を閲覧できます。
- 題名、著者、DOI、要点、限界を横断検索できます。
- テーマ別に絞り込み、出版年分布を確認できます。
- 各文献について、研究との直接的な関係、論文が支持する事実、限界を読み、一次情報またはDOIを開けます。

### 3.3 論文リーダー

- 書誌情報、要旨、背景、方法、結果、考察、結論を日本語または英語で通読できます。
- DOI、PMID、PMCID、ライセンス、研究資金、利益相反、データ可用性を確認できます。
- 完全な本文や参考文献を一次ソースで確認するためのリンクを利用できます。

### 3.4 方法・数式・表

- Fickの第2法則、透過率、回帰、RMSE、R²、MN表面積など、原著の式(1)〜(11)を確認できます。
- Fickモデルの5つの仮定を確認できます。
- 原著Table 1〜3の入力範囲とハイパーパラメータを参照できます。
- Table 2とData S1の表記差、Data S2のコードや入力ファイルの不足を確認できます。

### 3.5 モデル評価

- 原著が比較した Fick、重回帰、Random Forest、XGBoost の違いを確認できます。
- 原著Table 4のRMSE・R²をアウトカム別にチャートと表で比較できます。
- 原著が報告した順位、Random Forest／XGBoostの主要特徴量、Fick感度解析の方向を確認できます。
- R²を「正解率」と誤解しないための説明や、Table 4の数値が公開情報だけでは独立再計算できない理由を確認できます。

画面上部の「報告性能」からも原著Table 4の転記値を開けます。これらは報告値であり、アプリが原著と同一の分割・実装で再現した値ではありません。

### 3.6 全8図ガイド

- 原著Figure 1〜8を、図の目的、読み方、関連する数値、注意点とともに確認できます。
- 4手法、学習・評価フロー、データ構成、Fickの時間発展と感度、予測対実測、特徴量重要度を追えます。
- 原図の表記差、再現不能な要素、補足資料の再現性を監査できます。
- 原著および補足資料の一次ソースを開けます。

### 3.7 出典データ

- Data S1を薬物、皮膚、アウトカムで絞り込み、実測散布図として確認できます。
- 任意の観測を選び、全11列を丸めていないJSONとして表示・コピーできます。
- 行数、列数、薬物別件数、入力範囲、解析エラー、100%超の透過率を確認できます。
- `amount = loading × percentage / 100` の整合性と最大絶対残差を監査できます。
- CSVの `References` 列に含まれる実験出典を確認できます。

### 3.8 出典・完全性

- Data S1、無作為分割比、Data S2コード、Table 4など、公開されている要素と未公開の要素を一覧できます。
- train/test行割当、分割生成コード、学習済み係数・forest・boosterが未公開であることを確認できます。
- データの決定論的整合性、パースエラー、100%超の値を監査できます。

## 4. 自分の研究モードでできること

### 4.1 研究ダッシュボード

- 自分のCSVを読み込み、研究データ、Fick 85%監査、モデル選定へ移動できます。
- 現在のデータと、公開Data S1を用いた既存の探索結果の位置づけを確認できます。
- 発表可能性に必要な追加データや、現状では満たしていない検証条件を把握できます。

### 4.2 Fick 85% エビデンス

未見の実験条件に対するFick型モデルの説明力を監査する機能です。

- 似た行を `drug × skin × MN type` のfamilyと、時間を除いたproxy conditionへまとめます。
- proxy conditionを一つずつ隠し、残りの条件だけでFick有限平板型モデルをfitして透過率を予測します。
- pooled OOF R²、RMSE、MAE、condition均等R²、family中心化R²、family別R²を確認できます。
- 固定OOF予測のcondition-cluster再標本化、percentile、`R² ≥ 0.85`となる構成比を確認できます。
- familyを丸ごと除外するstress testで、より厳しい一般化性能を確認できます。
- 保存runを選ぶたびに元データから再監査し、run JSONと監査sidecar JSONを書き出せます。
- 最近のraw runを最大10件、このMacに保存できます。

ここでの「85%」は薬物の透過割合や予測正解率ではなく、将来の外部確認で目標とする `R² ≥ 0.85` を意味します。現在のproxy検証は探索的・事後的であり、原著Table 4、原著の2D Fickモデル、独立外部検証とは別物です。

### 4.3 データ比較

- 現在のデータを薬物別、皮膚別、MNタイプ別に可視化できます。
- MN長、表面積、負荷量、透過量、透過率などの分布を比較できます。
- 入力条件に対する透過量・透過率の実測トレンドを確認できます。
- 各薬物の最小値、中央値、最大値、観測数を一覧できます。
- Data S1と同じ11列形式の類似研究CSVを別スロットへ読み込み、Yuan 2023と横並びで比較できます。
- 比較研究の薬物名は原著の6薬物以外でも使用できます。

比較は記述的な可視化であり、条件差を調整した因果比較ではありません。比較CSVは、現在の研究CSVやData S1へ混ぜられません。

### 4.4 エクスペリメント

原著の統計解析プロトコルを、現在のCSVに対して再構成して実行します。

選択できる目的変数:

- 累積透過量（µg/cm²）
- 累積透過率（%）

固定される7特徴量:

1. 薬物負荷量
2. 分子量
3. MN長
4. 皮膚コード
5. MNタイプコード
6. MN表面積
7. 透過時間

実行されるモデル:

- 切片なし重回帰（native OLS）
- 500本のnative Random Forest
- native Gradient Tree Boosting

検証方法:

- 70:30の行分割
- 1薬物を学習から完全に除く leave-one-drug-out

実行後は次を確認できます。

- RMSE、MAE、R²、および診断用 `sqrt(SSE)`
- 実測値と予測値の散布図
- 学習・テスト行数と各行の割当
- 薬物別の分割件数
- 同一条件が学習とテストへまたがるデータ漏洩リスク
- データhash、seed、エンジン名、設定、所要時間、警告、再現性の限界

完全な設定、分割行ID、指標、各行の予測、来歴をrun JSONへ書き出せます。最近の成功runはモード別に最大10件、このMacへ保存されます。

通常の画面構成では、この実行機能は「自分の研究」にだけ表示されます。Data S1を使った開発者向け再現確認経路はありますが、その結果も原著の非公開splitやR/XGBoost実装を再現したものとは扱いません。原著値の閲覧は「論文エビデンス」の「モデル評価」で行います。

### 4.5 モデル選定

固定11列形式に限らない、一般的な表形式回帰のワークフローです。

1. 現在の研究データ、比較研究データ、または任意の学習CSVを選びます。
2. 数値の目的変数、分割グループ、説明変数を指定します。
3. データ漏洩を検査し、最大5-foldの内部交差検証を実行します。
4. 平均値baseline、Ridge回帰、Random Forest、Gradient Boostingを同じfoldで比較します。
5. RMSEが最小の候補を確認し、任意の候補を全有効行で最終学習します。
6. 学習済みモデルをJSONとして保存、再読込、削除できます。
7. 必要な入力列だけを持つテンプレートCSVを書き出せます。
8. 未知CSVを一括予測し、結果CSVを書き出せます。

分割グループには `run_id`、`curve_id`、患者、batch、薬物などを指定できます。同じグループの行は同じfoldに保たれます。グループを指定しない行単位CVも可能ですが、複数時点や反復測定を含む研究では通常推奨されません。

漏洩チェックでは、IDらしい列を目的変数・説明変数へ入れる設定や、透過量と透過率のように数式で結ばれたoutcomeの併用を検出し、重大な問題がある場合は学習を止めます。

数値列はfold内中央値で補完し、カテゴリ列はfold内でエンコードします。空列や、値が1種類しかないカテゴリ列、13種類以上のカテゴリ列など、エンコードできない列は学習から除外されます。

### 4.6 未知CSVへの予測と外部評価

学習済みモデルがある場合、次の2通りで使用できます。

- 目的変数なし: 予測値だけを生成する
- 同名の目的変数あり: モデルを再学習せず、RMSE・MAE・R²を計算する

予測時には、欠測・非有限値、学習時に存在しなかったカテゴリ、学習範囲外の数値を診断します。出力CSVには元の入力列、元CSV行番号、予測値、目的変数がある場合は実測値と残差、artifact IDが含まれます。

「現在データで操作練習」は学習に使ったデータを再予測するだけであり、外部性能として報告できません。外部評価と呼べるのは、モデル、特徴量、閾値を決める際に一度も見ていない独立runのCSVを評価した場合だけです。

### 4.7 4モデル透過曲線

- 薬物、皮膚、MNタイプ、負荷量、MN長、MN表面積、表示時間を指定できます。
- Fick、重回帰、Random Forest、Gradient Boosting代替の探索的時間曲線を比較できます。
- 現在の研究データの実測点を曲線上へ重ねられます。
- 11列形式の in vitro CSVを別スロットへ読み込み、条件が一致する観測を重ねられます。
- 一致観測に対する各曲線のRMSE・MAEを計算できます。

曲線は現在のCSVで再学習した探索用表示です。原著の学習済み係数、forest、XGBoost boosterを再生したものではありません。

### 4.8 皮膚透過

- 薬物、皮膚、MNタイプ、アウトカムで実測点を絞り込めます。
- 時間に対する透過量または透過率を散布図で確認できます。
- hydrogel MNとplastic MNについて、Franz-cell試験の概念的な4段階を確認できます。

公開データにはseries／replicate関係がないため、散布図の点は単一の時間曲線として接続されません。工程表示も非定量の概念図です。

### 4.9 自分の研究データ／研究監査

- 自分のCSVをData S1と同じ観測エクスプローラで確認できます。
- 各行の全11列をJSONとして表示・コピーできます。
- 型、有限値、カテゴリコード、値域、100%超の値、透過量と透過率の整合性を監査できます。
- `References` 列を自分の研究データの来歴として確認できます。
- 発表へ進む前に必要な独立run／curve ID、盲検外部outcome、信頼下限などの不足を確認できます。

## 5. Fick関連機能の違い

Fickという名前を持つ機能は目的が異なります。

| 機能 | 目的 | 主な出力 | 解釈上の位置づけ |
| --- | --- | --- | --- |
| Fick 2D有限差分ラボ | 拡散係数、MN長、MN数、搭載量、時間を変え、数値法を試す | 累積透過曲線、最終量、最終率、反復数、質量収支誤差 | 数値法の粗視化プレビュー |
| Fick 85% エビデンス | 隠した条件の透過率をFick型proxyで予測できるか監査する | OOF R²、誤差、再標本化、family stress | 探索的な説明力監査 |
| エクスペリメント内のFick報告値 | 原著4手法の一つとして結果を読む | Table 4転記値または報告比較 | 原著報告値であり独立再現値ではない |
| 4モデル透過曲線のFick線 | 選択条件の時間変化を他モデルと比較する | 探索的な単調飽和曲線 | 現在データに合わせた参照曲線 |

2D有限差分ラボでは、拡散係数50〜1,000 µm²/min、MN長700〜1,250 µm、搭載量50〜70,940 µg、MN数64または351、時間0.25〜50 hを指定できます。25 µm格子、1,000 µm皮膚、250 µm半領域を用い、陽解法の安定条件を満たす時間刻みを自動選択します。これは原著の2 µm格子によるTable 4予測ではありません。

## 6. CSVの種類と要件

### 6.1 自分の研究／エクスペリメント用CSV

Data S1と同じ11列、同じ順序が必要です。

```text
Drug name,Drug loading in MN patch (µg),Drug MW (Dalton),MN Length (mm),Skin type (rat =1; human = 2),MN type (hydrogel =1; plastic = 2),MN surface area (mm2),Permeation time (hour),Drug permeation percentage,Drug permeation amounts (µg/cm2),References
```

追加条件:

- `Drug name` は現在のエクスペリメントでは `BSA`、`copper ions`、`GHK peptide`、`Rhodamine B`、`lidocaine`、`caffeine` の6表記を使用します。
- skinはラット=`1`、ヒト=`2`です。
- MN typeはhydrogel=`1`、plastic=`2`です。
- 数値は有限かつ非負で、主要入力は正値が必要です。
- 空データやスキーマエラーのあるCSVは有効な研究データとして読み込まれません。
- 出典や実験runの来歴は `References` 列と、別途保存するプロトコルで管理します。

### 6.2 類似研究／in vitro比較用CSV

同じ11列・同じ順序を使用しますが、薬物名は原著6種以外でも構いません。比較用CSVは可視化・横並び比較専用で、現在の研究データやモデル学習へ自動混入しません。

### 6.3 汎用モデル選定用CSV

- 1行目に重複のない列名が必要です。
- 2列以上必要です。
- 有限な目的変数を持つ行が20件以上必要です。
- 最大5,000行です。
- 目的変数は数値列から選びます。
- 目的変数以外の列は、数値またはカテゴリ説明変数として扱えます。
- 分割グループ列は任意ですが、反復測定を含む場合は指定を推奨します。

## 7. 保存・書き出し

| 保存物 | 内容 |
| --- | --- |
| モデルJSON | 前処理、学習済みnativeモデル、列定義、カテゴリ、学習範囲、内部CV要約、dataset hash、artifact ID |
| 予測CSV | 元入力、元CSV行番号、予測、任意の実測値・残差、artifact ID |
| Experiment run JSON | 設定、データhash、分割行ID、モデル設定、指標、予測、警告、来歴 |
| Fick proxy run JSON | 設定、fold、全予測、percentile、stress test、警告、限界 |
| Fick監査sidecar JSON | 保存runを独立再計算した監査結果 |
| アプリ内モデル | 直近の学習済みモデル1件をUserDefaultsへ保存 |
| アプリ内run履歴 | 通常ExperimentとFick proxyをそれぞれ最大10件保存 |

自分の研究CSVそのものと比較CSVは、アプリ再起動後の永続保存を前提としていません。重要な研究成果は、元CSV、モデルJSON、予測CSV、run JSON、プロトコルMarkdownを共通の研究run IDで別途保管してください。

## 8. 代表的な使い方

### A. 原著を理解・監査する

1. 「論文エビデンス」を選びます。
2. 「論文の概要」から研究設計を確認します。
3. 「方法・数式・表」と「全8図ガイド」で式、条件、図を確認します。
4. 「モデル評価」でTable 4の報告性能と整合性上の注意を確認します。
5. 「出典データ」と「出典・完全性」でData S1と公開資料の限界を監査します。

### B. 自分の11列データで原著型の比較実験を行う

1. 「自分の研究」を選び、実験CSVを読み込みます。
2. 「自分の研究データ」でエラー、値域、References、100%超の値を確認します。
3. 「エクスペリメント」で目的変数と検証方法を選びます。
4. 未知薬物を想定する場合はleave-one-drug-outを使います。
5. 指標だけでなく、分割、同一条件重複、予測散布図、警告を確認します。
6. run JSONを書き出し、元CSVと一緒に保存します。

### C. 任意のCSVから予測モデルを作る

1. 「モデル選定」で学習CSVを読み込みます。
2. 目的変数、分割グループ、説明変数を確認します。
3. 漏洩チェックを解消して内部CVを実行します。
4. baselineと3候補を比較し、最終モデルを選びます。
5. 全データで最終学習し、モデルJSONと入力テンプレートを書き出します。
6. 未使用の独立CSVを予測し、予測CSVと外部評価指標を保存します。

### D. Fick計算を検討する

1. 数値法そのものを確認したい場合は「エクスペリメント」のFick 2D有限差分ラボを使用します。
2. 隠した条件への説明力を監査したい場合は「Fick 85% エビデンス」を使用します。
3. 原著が報告したFickと他モデルの順位を読みたい場合は「モデル評価」を使用します。

## 9. このプラットフォームで保証できないこと

- 原著のTable 4を完全に再現すること
- 原著と数値的に同一のR `randomForest` やXGBoostモデルを再生すること
- 非公開のtrain/test行、学習済みモデル、個別予測を復元すること
- 行単位CVや内部CVだけで、新規薬物・新規患者・新規batchへの一般化を証明すること
- スキーマ検証だけで、測定品質、研究設計、再現性、科学的妥当性を保証すること
- 特徴量重要度から因果関係を判断すること
- 診断、処方、投与量、治療効果、毒性、安全性、患者転帰を判断すること

このアプリは研究、教育、データ品質確認、解析計画、計算実験のためのツールです。臨床意思決定ツールではありません。
